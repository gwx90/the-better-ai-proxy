# The better AI proxy

面向 **FlClash / Mihomo** 的通用分流模板：订阅独立管理，地区与选线策略自动发现来源，ChatGPT、Claude、Gemini 分别选择出口。

**仓库不包含机场订阅链接、节点凭据或个人配置。** 添加或更换机场通常只需在 FlClash 中绑定来源，无需改写 YAML。

## 分流结构

```text
自己添加的订阅
      ↓ 绑定一次
🧩 机场订阅（隐藏的来源入口）
      ↓ 自动发现与筛选
日本 / 中国台湾 / 香港 / 美国 / 新加坡 / 其他地区
最低延迟 / 故障转移 / 负载均衡 / 本机直连
      ↓ 服务分别选择
Google / ChatGPT / Claude / Gemini / 其他服务
```

- **45 个策略组、1,858 条规则**，保留服务分类与广告拦截。
- **ChatGPT → Claude → Gemini** 排列在 Google 后、Microsoft 前，均为普通选择组；可使用全部地区和选线策略。
- Google 和三个 AI 服务的初始选项为美国地区，随后可自由改选。Gemini 不绑定某个美国节点，也没有美国节点筛选限制。
- 所有订阅来源按相同规则参与自动选线，不根据某次流量状态添加特殊标签。
- localhost、回环与局域网地址优先直连，适用于需要本机回调或本地服务的应用。
- 地区按节点名称识别；测速与故障转移依据健康检查，不保证账号地区资格或具体服务的可用性。

## 使用方式

本模板按 **FlClash 0.9.2 / Mihomo 1.19.33** 的原生自定义配置方式整理。其他版本的界面名称和兼容性可能不同。

1. 先备份现有 FlClash 配置。
2. 在“配置”页添加自己的订阅并同步成功。订阅链接保留在这些独立条目中。
3. 新建一个**自定义配置**，在编辑器中选择“导入 → 通过文件导入”，选择 [`templates/routing.yaml`](templates/routing.yaml)。
4. 打开策略组 **🧩 机场订阅** →“节点 → 添加节点”，分类选择“代理提供者”，绑定自己的订阅。
5. 在“外部资源 → 代理”中为各来源设置唯一附加前缀（`Additional Prefix`），例如 `【来源A】`、`【来源B】`，避免节点重名。
6. 保存并退出编辑，然后启用这个自定义配置。

**首次启用前先绑定来源。** 仓库模板的 `proxy-providers` 和来源绑定列表为空；没有订阅时，它不会凭空提供代理节点。

导入到原生自定义配置后，通常无需在配置列表长期保留一个单独的 YAML 文件条目。原订阅仍由 FlClash 管理和更新，自定义配置引用它们的缓存。

## 新增、替换或更新机场

新增机场：

> 添加并同步订阅 → 绑定到“🧩 机场订阅” → 设置唯一前缀 → 保存。

节点会按现有筛选进入对应地区和自动策略，服务分组继续引用这些地区和策略，**不用逐个改服务组，也不用重新生成 YAML**。

如果机场使用了现有筛选无法识别的地区别名，需要补充相应通用地区规则。订阅中的流量、到期等提示节点会通过通用过滤规则排除，BitTorrent 专用节点不进入普通自动池。

删除来源时，先从“🧩 机场订阅”中解除绑定，再删除原订阅条目。替换订阅地址或日常更新在原订阅条目中完成。

## 模板维护

```sh
ruby scripts/check.rb
```

检查只使用 Ruby 标准库，既不访问网络，也不读取 FlClash 数据库或本机订阅。内容包括分组引用、循环引用、规则目标、AI 服务选项、本机直连、来源解耦，以及模拟新增来源的地区和自动选线发现。

FlClash 中导入后的原生配置是独立副本，不会自动跟随本仓库文件变更。更新模板后，需要重新导入并检查来源绑定及覆盖选项。更新活动配置时可使用原生编辑器在线应用，无需退出 FlClash 或停止代理进程。

## 文件与隐私

| 文件 | 内容 |
| --- | --- |
| `templates/routing.yaml` | 无订阅链接和静态节点的分流模板 |
| `scripts/check.rb` | 可独立运行的模板检查 |
| `.gitignore` | 默认忽略所有文件，只允许提交上述文件与本说明 |

不要提交订阅导出、完整运行配置、数据库、日志、节点缓存或备份。即使仓库是私有的，也应将这些内容放在仓库之外。
